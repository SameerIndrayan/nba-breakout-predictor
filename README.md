# NBA Breakout Season Detector

A machine learning system that predicts which young NBA players are about to have a
**breakout season**, using only their *prior-season* stats. The whole pipeline is built
to avoid look-ahead bias: the model is trained on older seasons and tested on newer ones,
so it never gets to peek at the future when making a prediction.

Given a player's season (age, minutes, scoring, efficiency, usage, playmaking, etc.), the
model outputs a probability that the player breaks out the *following* season.

---

## What counts as a "breakout"?

A player-season transition (year `N` → year `N+1`) is labeled a breakout when **all** of
these are true:

| Condition | Threshold |
|---|---|
| Age (prior season) | ≤ 26 |
| Games played, both seasons | ≥ 30 each |
| Points-per-game increase | ≥ 5 more PPG |
| Relative scoring increase | ≥ 40% |
| Minutes increase | ≥ 3 more MPG |
| True Shooting % change | did **not** drop by more than 2 points |

This definition catches leaps like SGA's first jump, Tyrese Maxey, Jaylen Brown, Jordan
Poole's Y2→Y3, Jalen Brunson's 2022-23 Knicks year, and Nickeil Alexander-Walker's
2025-26 season. Across 21 seasons it labels **239 breakouts out of 8,355 transitions
(~2.9%)** — deliberately rare, which is what makes it a hard prediction problem.

## Usage

Run the three scripts **in order, from the repository root** (the paths are relative, so
running them from inside `src/` will fail):

```bash
python src/collect.py     # ~5-10 min: pulls 21 seasons from nba_api. Writes data/player_stats_all_seasons.csv
python src/features.py    # builds transitions + labels.        Writes data/labeled_transitions.csv
python src/model.py       # trains the model + prints results.  Reads  data/labeled_transitions.csv
```

`collect.py` hits the live `nba_api` for all 21 seasons and is the slow step — it sleeps
between requests to avoid rate limits, so expect several minutes. `features.py` and
`model.py` run in seconds. The scripts create the `data/` folder automatically if it
doesn't exist.

## How it works

**1. Collection (`collect.py`)** — pulls both *base* per-game stats and *advanced* stats
(USG%, TS%, AST%, PIE, rebound rates) from `leaguedashplayerstats` for 21 seasons
(2005-06 through 2025-26), producing 10,595 player-seasons × 31 columns.

**2. Feature engineering (`features.py`)** — sorts each player's seasons chronologically
and uses pandas `.shift(1)` to pair each season with the one before it. For every
transition it computes `PREV_*` features (last season's stats), deltas (`PTS_DELTA`,
`MIN_DELTA`, `TS_DELTA`), per-36 rates (`PREV_PTS_PER36`, etc.), and a `TEAM_CHANGED`
flag. Then it applies the breakout definition above to label each transition.

**3. Modeling (`model.py`)** — does a **temporal split** (train on seasons ≤ 2018-19, test
on ≥ 2019-20) so the model can't learn from the future. Trains a logistic regression with
`class_weight="balanced"` to handle the rare positive class. Features used:

```
PREV_AGE, PREV_GP, PREV_MIN, PREV_PTS, PREV_REB, PREV_AST,
PREV_FG_PCT, PREV_FG3_PCT, PREV_FT_PCT, PREV_TS_PCT,
PREV_USG_PCT, PREV_AST_PCT, PREV_PIE,
PREV_PTS_PER36, PREV_REB_PER36, PREV_AST_PER36,
TEAM_CHANGED
```

## Current results (logistic regression)

Temporal test set (seasons ≥ 2019-20): 3,205 transitions, 80 real breakouts.

| Metric | Value |
|---|---|
| ROC AUC | **0.839** |
| Breakout recall | **75%** (catches 3 of 4 real breakouts) |
| Breakout precision | 8% (many false positives — see limitations) |

**Top positive predictors** (push probability up): `PREV_GP` (+1.18), `PREV_PIE` (+1.16),
`PREV_USG_PCT` (+0.54), `PREV_AST_PER36` (+0.49).

**Top negative predictors** (push probability down): `PREV_AGE` (−1.85), `PREV_PTS`
(−1.25), `PREV_MIN` (−0.75). This matches intuition — breakout candidates are **young and
underutilized**, not already-established scorers.

Correctly flagged breakouts include SGA (0.79), Tyrese Maxey (0.96), NAW's first breakout
(0.90), Jordan Poole Y2→Y3 (0.72), Jaylen Brown (0.63), plus Matas Buzelis, Devin Vassell,
and Alperen Sengun.

## Known limitations

1. **Low-minute noise.** Very-low-minute players get extreme per-36 stats from tiny sample
   sizes and can pollute the top of the ranked list (e.g. Stanley Umude at 2 PPG ranked #1
   with 0.9999 probability). This is a data-eligibility problem, not just a model problem —
   a minutes/games filter on candidates is the real fix.
2. **Role-change breakouts.** The model misses situation-driven leaps like Brunson's
   2022-23 Knicks year (only 0.11 probability). Those are caused by a change in role/team
   context, not by a development curve the stats can see. `TEAM_CHANGED` was added but
   carries a *negative* coefficient, because most team changes are journeymen rather than
   lead-guard signings.
